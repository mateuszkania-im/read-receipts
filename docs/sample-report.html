09Method and limits

Unreferenced
A read is unreferenced when nothing the agent did after it refers back to it. A later edit, command or text refers back to it through an edit of the file; its full path, a path suffix (the end of its path) no other file of the session shares, or its basename when that is 6 or more characters with a dot; an identifier declared in it; for a test file, one of its test titles, or an edit of the module under test. It includes reads used to rule something out, so it does not mean the read was useless. Full rules: spec 6.3, https://github.com/mateuszkania-im/read-receipts/blob/main/docs/superpowers/specs/2026-11-01-agent-ledger-design.md#63-reads-and-unreferenced-reads
Referenced
A read is referenced when a later edit, path mention, identifier, test title or edit of the module under test refers back to it. It includes files named only to dismiss them.
≈
An estimate: tokens counted as characters / 4. Assistant output tokens are exact.
≥
A lower bound: some requests had no usage or no price and are left out.
Precision and miss rate
Precision of "unreferenced" against blind labels: 25.0% (95% CI 14.6% to 39.4%): 11 of 44 reads called unreferenced were unused, 27 more unclear (blind labels, heuristic v1 before test-file rules 4 and 5, so conservative for the current heuristic). Unreferenced is an upper bound on unused reads. Miss rate of "referenced": 3.7% (95% CI 1.3% to 10.3%): 3 of 81 reads called referenced were unused (held-out sample, blind). Recall is not published: the labelled sample was stratified by the heuristic's call, so recall cannot be estimated without reweighting.
